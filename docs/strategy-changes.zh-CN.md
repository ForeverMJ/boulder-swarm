更新日期：2026-10-10。基线：`ca34d42b29c391c7f00eb394c207300d61b37f2a`。

覆盖本功能分支的全部修改，包括进展机制、CLI 修复及候选策略比较。协议见 [PROGRESS.md](../PROGRESS.md)，独立测试交接见 [测试指南](strategy-testing.zh-CN.md)。

## 目标与结论

路线由 Agent 自主提出。运行时保存证据、限制重复尝试，并在切换路线时比较原方法与候选方法。系统不预设算法路线，也不把计划中的理由当作真实进展。

当前实现了机制及工程测试，**尚未证明真实模型因此提出更好的策略、完成更多任务或降低总成本**。配对选择均标记 `provisional: true`。功能需显式启用；原 goal.yaml 未改变，现有研究任务未自动开启。

## 当前执行流程

1. 首轮从 main 开始；后续 progress 任务从最新 receipt 提交恢复。
2. 规划 Agent 接收任务限制、原方法、检查结果、失败原因、证据及比较历史，提出 continue / switch / stop。
3. 校验范围、引用和机械约束。首次 switch 没有对照，直接执行；continue 保留方法并执行一次。
4. 后续 switch 触发配对：双方从同一提交、相同试跑前历史出发，工作区隔离，顺序交替。
5. 双方退出、无残留进程且稳定后，提交产物并验证。
6. 双方有效、验收总数相同且覆盖不低于起点时，候选只有在增加覆盖或达到原验收、且不降低通过测试数量时才可能胜出。平局保留原策略。
7. 比较不完整、执行异常或覆盖退化：保留起点并反馈给有限重新规划；不把基础设施故障算作策略被击败。
8. 选中提交快进到任务分支，最终仍须原合并 gate。未选中试跑不提升已接受覆盖高水位。

## 证据、重启与预算

- `trajectories/progress-decisions-v2.jsonl` 追加计划、理由、实验、证据、观察、提交和耗时；可选 comparison 记录双方结果及选择。兼容旧 v2；损坏记录拒绝继续。停止状态不会因重启自动清除。
- `trajectories/strategy-trials-v1.jsonl` 逐步保存开始、每个试跑、选择与应用。试验分支和工作区保留。
- 覆盖是固定范围内的累计数量，跨路线共享高水位。超时不是穷尽；有限范围穷尽不是总体问题无解。
- 规划最多 120 秒。起点验证后双方各获得剩余时间的 35%，预留 30% 给检查和稳定等待。第二条路线无法获得完整额度时不缩短额度硬比。
- 一次切换通常有规划及两条试跑共三次模型调用，全部耗时计入，包括败选或失败路线；选中后不追加执行。初始/continue 路径通常两次调用。

## 已知限制

- 配对结果是暂时选择；未实现重复采样、置信区间、隐藏评测、跨任务迁移或学习式预算分配。
- 相同执行上限不等于相同 token、费用或实际耗时。Git 和外围操作保留原超时，没有严格整体实时上限。
- 验收保存数量而非测试身份。等数量不能排除通过项互换、测试语义改变或同数值覆盖对应不同对象。独立效果评估应使用不可被 worker 修改的验收。
- Git worktree 不是安全沙箱；禁止读取其他试跑输出是提示约束。
- 恢复任务快照不自动整合更新的 main，可能发生整合冲突。
- 分支和工作区不自动清理；历史上下文未有界压缩。
- 中断记录可审计，但无 exactly-once 恢复；突然崩溃可能未记全 supervisor 成本。未完成试跑不自动晋升。
- 引用校验不证明解释逻辑正确；字符串去重不识别所有改写重复。
- checker hash 只含入口文件与策略配置；依赖变更需更新 scope/version。
- CLI 修复针对原生可执行文件；Windows cmd/bat 仍经 shell，需继续审查特殊字符和 CLI 版本差异。

借鉴 [GEPA](https://arxiv.org/abs/2507.19457) 的候选实测、[SEAGym](https://arxiv.org/abs/2606.17546) 的评估纪律和 [PIVOT-KG](https://arxiv.org/abs/2609.32677) 的成对验证思想。本分支不是完整复现，论文结果不能替代本项目实测。
