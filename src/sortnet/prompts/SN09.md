# SN09 - long search: beat the best-known size for n=14

You are the worker for task SN09, one round of a LONG-RUNNING search. The best-known
sorting network for 14 inputs has 51 comparators; a correct network with fewer would
be a new record. This task is progress-protocol managed: your round is a time slice,
your checkpoint outlives you, and the next round resumes from your commit.

## The checkpoint contract (load-bearing)

State file: `src/sortnet/attempts/SN09_state.json` — one JSON object, ASCII only:

```json
{
  "scope": "n14le50",
  "n": 14,
  "covered": <integer, cumulative candidate count across ALL rounds>,
  "prevHash": <sha256 of the previous round's state file, or null on round 1>,
  "best": <the best CORRECT network found so far, {"n":14,"comparators":[[a,b],...]}, or null>,
  "note": "<=500 chars: what THIS round tried and measured - facts, not verdicts"
}
```

Rules:
1. On start, read `SN09_state.json` if present (it persists from previous rounds).
   Compute its hash BEFORE overwriting: `sha256sum src/sortnet/attempts/SN09_state.json`
   — that hex digest is your new `prevHash`. If absent, `prevHash` is `null`.
2. `covered` MUST strictly increase every round (your round's evaluations + the
   previous total). The trusted checker rejects non-increasing or mis-chained states.
3. `best` is verified exhaustively by the supervisor; a wrong network voids the round.
4. WRITE THE CHECKPOINT BEFORE MINUTE 20. The 30-minute timeout kills mid-search;
   the checkpoint is what survives. Searching without checkpointing is wasted work.

## Deliverables (allowed file set — no others)

- `src/sortnet/attempts/SN09_state.json` (checkpoint; REQUIRED every round)
- `src/sortnet/attempts/SN09_search.ts` (search machinery; _search.ts files are
  excluded from scoreboard scans, so keep it as one file)
- `src/sortnet/attempts/SN09_net14.ts` + `SN09_net14.test.ts` — create ONLY if you
  found a correct network with at most 50 comparators; the test asserts
  `checker.verify(network).correct` and the size bound. Do not create them otherwise.

## Strategy

- Read `src/sortnet/ATTEMPTS.ndjson` (if present) first: prior rounds' facts — what was
  tried, how much was evaluated, what happened. Evidence, not prohibitions.
- Resume, don't restart: use the checkpoint's covered/note to continue or pivot.
- Most slack lives in the last layers; known approaches: prefix/suffix re-optimization,
  remove-and-rewire, Green-filter style layer pruning, SAT-style layer enumeration.
- A correct smaller network beats everything; the marker `N14BEATBESTKNOWN=SN09_net14.ts`
  on `bun src/sortnet/scoreboard.ts` is the only completion signal.

You may import from `src/sortnet/checker.ts`, `src/sortnet/types.ts`, and
`src/sortnet/tools/batcher.ts`. You may read any repository file. You MUST NOT modify
any file outside your allowed set.
