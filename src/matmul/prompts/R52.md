## The target

`src/matmul/attempts/T12c_absorb_best.ts` is a rank-22 bilinear scheme for
`<3,3,3>` that is wrong at exactly **one** tensor entry out of 729:

    (a,b,c) = (7,4,7),  got = 0,  want = 1

which decodes to output `(i,j) = (2,1)` at inner index `k = 1`. It is the
closest thing this repository has to a solution, so it is worth one structured

## What is already established, do not rediscover it

1. No single-coefficient change fixes it. All 3390 candidates (22 triples × 27
   coefficients × values `[-3,-2,-1,1,2,3]`) were checked against the real
   verifier. `src/matmul/tools/absorbRepair.ts` has this as
   `singleCoefficientRepair`.
2. The entry is the sum `Σ_t u_t[7] · v_t[4] · w_t[7]`, and for **every** one of
   the 22 triples at most one of those three coordinates is nonzero. So no single
   edit can move the entry.
3. Six triples have exactly one coordinate in place and could reach the entry if a
   second were activated: **5, 7, 9, 14, 19, 20**. Their supports are

   ```
   t=5   uSupp=[0,1,2,7,8]  vSupp=[5]     wSupp=[8]
   t=7   uSupp=[0..7]       vSupp=[3]     wSupp=[6]
   t=9   uSupp=[8]          vSupp=[7]     wSupp=[0,2,3,5,7,8]
   t=14  uSupp=[6]          vSupp=[1]     wSupp=[7]
   t=19  uSupp=[1]          vSupp=[3,4,5,6,7,8]  wSupp=[1]
   t=20  uSupp=[4]          vSupp=[4]     wSupp=[4]
   ```

4. **No triple has `vSupp` exactly `{4}` together with `uSupp` exactly `{7}`.**
   So there is no clean single-triple repair: any activation of `u_t[7]` when
   `v_t = e_4` also perturbs every entry `(a, 4, c)` for each `a` in `uSupp(t)`,
   and that collateral has to be cancelled by changes to other triples.

## What to build

A search over **coordinated multi-triple changes** whose induced tensor change is
exactly `e_{7,4,7}` and zero everywhere else. Report what it finds; a null result
that is honestly bounded is an acceptable outcome and is what the judge expects if
the search is exhaustive within its stated budget.

Design notes:

- The oracle is `verify` from `src/matmul/checker.ts`. Never re-derive correctness.
- Work by computing the *induced change* of a candidate move set and comparing it
  to `e_{7,4,7}`, rather than re-running the full check on every trial if you can
  avoid it. `mismatchSites` in `absorbRepair.ts` is the reference for locating
  damage.
- A move that changes `u_t[a]` by `δ` changes entry `(a,b,c)` by `δ·v_t[b]·w_t[c]`.
  Use that to reason about collateral instead of guessing.
- Restrict candidate triples to 5, 7, 9, 14, 19, 20 and to coordinates `u[7]`,
  `v[4]`, `w[7]`, since nothing else can influence the target entry. A move on
  any other coordinate can only be useful as compensation.
- Keep the coefficient range small. If you widen it, say so in the output.
