## The problem, precisely

`primeCover(maxN)` must cover n in [2..maxN] (checked at 1_000_000) within 45 s of
runtime, with the same fail-honest Es4Summary semantics. Direct sweeps are mathematically
hopeless here (they scale Θ(N²·slow) — E1's algorithm extrapolates to ~12 minutes at
this N), so you must attack the structure:

1. **Scaling lemma (your foundation).** If 4/n = 1/x + 1/y + 1/z then for every
   positive integer k: 4/(k·n) = 1/(k·x) + 1/(k·y) + 1/(k·z). So if n is covered, n·k
   is covered for free. Verify only the n with no smaller covered divisor — sweep
   composites out entirely and check PRIMES (then everything else is covered by
   induction).

2. **Prime reduction.** Total prime work Σ_{p≤N} window(p)/2 is still too slow raw.
   So prove (or cite precisely with your justification) elementary identities that
   cover whole residue classes of primes, and leave only a thin set of primes to the
   explicit divisor search. Literature-shaped hint (you must re-derive, not transcribe
   blindly): for most residue classes modulo small numbers, 4/p admits an explicit
   3-term Egyptian fraction built from (p±1), (p±2), (p±3), (p±5) divisibility — the
   classes that survive these identities are known to be O(1) fraction of all primes
   and are exactly where your exact search budget must concentrate.
